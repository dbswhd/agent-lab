# Room Ideation — Checkpoint A 결과

> **판정일:** 2026-09-13
> **범위:** RI-CASE-01~03 development cases 3건
> **판정 상태:** provisional pass
> **주의:** 아래 점수는 실제 사용 후 설문이 아닌, live A/B 산출물에 대한 Codex의 객관적 대리지표다. 사용자 효용과 6건 전체 기준은 아직 미측정이다.

## 사례와 실행

| 사례 | 주제 | native 단일 에이전트 | Room | 주요 관찰 |
|---|---|---:|---:|---|
| RI-CASE-01 | 학교 사이트 학업 관리 | 155.7초 | 181.8초 | Room은 대안·보안 위험을 넓혔지만 후보 2/3의 구조화 실패와 메타 발화가 있었다. |
| RI-CASE-02 | 강의자료 기반 학습자료 | 215.2초 | 224.7초 | Room은 coverage·근거·추출 실패·문제 검증을 분리했다. native는 더 통합된 파이프라인을 제시했다. |
| RI-CASE-03 | 퀀트 트레이딩 환경 | 168.5초 | 131.4초 | Room은 승격 게이트·편향·kill switch를 보강했다. 어느 쪽도 수익성이나 실거래 적합성을 증명하지 못했다. |

모든 실행은 live provider로 수행했으며 mock은 사용하지 않았다. 비용은 기록되지 않아 비교하지 않는다. 일부 native 응답에는 다른 에이전트나 Room을 언급하는 메타 문장이 섞여 있어 엄밀한 blind A/B로 해석하지 않는다.

## 객관적 대리지표

점수는 1~5점이며, 아이디어가 얼마나 명확해졌는지, 실제 계획으로 옮길 수 있는지, 위험을 발견했는지, 개인 도구로 다시 사용할 가능성이 있는지를 평가한다.

| 사례 | 명확성 | 실행 가능성 | 위험 발견 | 예상 재사용 가치 | 평균 |
|---|---:|---:|---:|---:|---:|
| RI-CASE-01 | 4.0 | 4.0 | 4.0 | 4.0 | 4.00 |
| RI-CASE-02 | 5.0 | 4.5 | 5.0 | 4.5 | 4.75 |
| RI-CASE-03 | 4.5 | 3.5 | 5.0 | 3.5 | 4.13 |

## Room 비교 판정

- **RI-CASE-01:** Room과 native가 비슷하다. Room은 보안과 운영 위험을 더 많이 드러냈고, native는 더 짧고 일관된 제품 흐름을 만들었다.
- **RI-CASE-02:** Room이 근소하게 우세하다. 여러 관점이 “요약기”를 “근거·coverage·검증 컴파일러”로 바꾸는 데 기여했다.
- **RI-CASE-03:** 위험 검토에는 Room이 우세하다. 그러나 연구 전략의 유효성이나 실거래 준비도를 높였다는 증거는 없다.

따라서 Room은 모든 아이디어의 기본 실행기가 아니다. 방향 불확실성, 자료·운영 위험, 대안 간 trade-off가 큰 경우에만 호출하는 조건부 검토 단계로 둔다. 최종 계획은 한 명의 lead가 합성하고, Room은 독립적인 대안과 반론을 제공한다.

## Checkpoint A 판정

**provisional pass**로 기록한다.

근거는 세 가지다.

1. 세 사례 모두에서 Room이 단일 에이전트가 놓치기 쉬운 위험 또는 대안을 추가했다.
2. 특히 문서 학습자료와 퀀트 사례에서 품질 계약과 중단 기준이 실질적으로 구체화됐다.
3. 동시에 Room의 우월성이 보편적이지 않고, 응답 잡음과 latency가 존재한다는 한계도 확인됐다.

이 판정은 신규 UI 투자를 시험할 근거로는 충분하지만, Room 기본값 전환이나 시장 경쟁력의 증거는 아니다. holdout 3건, 실제 사용자 효용, 실제 외부 개발 착수가 RI-14의 최종 판정에 필요하다.

## Agent Lab에 반영한 출력 계약

idea lane의 후보와 최종 합성 결과는 `ideation.v1` 경계로 전달된다. 후보는 아래 필드를 기준으로 저장·검사한다.

```text
아이디어 요약
→ 사용자와 문제
→ 선택 가능한 방향
→ 선택한 방향과 버린 방향
→ 작동 방식과 MVP
→ 검증 지표와 실패 기준
→ 사실·제안·미확인 가정
→ 남은 질문
```

후보는 자연어 전체가 아니라 이 필드를 가진 구조화 envelope로 저장한다. 이를 통해 선택된 방향이 Scribe와 plan 단계에서 사라지지 않게 한다.

구현 상태:

- `src/agent_lab/room/context/ideation_quality.py`가 `ideation.v1` 필수 필드와 `ready`/`needs_review`를 계산한다.
- 후보 화면에는 도구 호출·레포 탐색 같은 내부 과정 문장을 제거하고, 원문은 `raw`로 보존한다.
- 레포·파일 구현 주장은 `ref: 경로#L줄` 또는 `ref: 경로:줄` 형태의 구체적 근거가 없으면 미확인 주장으로 분류한다.
- 선택된 후보만 기존 Scribe의 최종 합성 입력에 넣는다. `needs_review` 후보는 필드가 사실로 승격되지 않고 검토 항목으로 남는다.

현재 근거 검사는 인라인 경로·라인 형식을 확인하는 단계다. 실제 파일 존재와 줄 내용까지 확인하는 강화는 후속 작업으로 남겨 둔다.
